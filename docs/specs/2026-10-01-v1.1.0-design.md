# Reusable QR Codes 1.1.0 — logo, block, scan counter

Status: approved by standing rule ("go with recommended always for this project"), 2026-10-01.

## Goal

Three features, released together as 1.1.0:

1. An optional logo in the centre of each QR code.
2. A block that shows a QR code on any page.
3. A privacy-friendly scan counter per QR code.

## Hard constraints

- Existing QR codes must look and work exactly as before after the update. Every new option defaults to "off".
- The printed URL of a QR code never changes. Only its appearance and its counters change.
- Minimum WordPress stays 5.8 and PHP stays 7.4. Guard any newer function with `function_exists`.
- No build step. JavaScript is plain ES2015+ that uses the `wp.*` globals, like the existing admin scripts.
- No new third-party dependency. The QR library stays `assets/vendor/QrCodeStyling.min.js`.
- No personal data. The counter stores a number and a date per QR code: no IP address, no cookie, no user agent.
- Follow the existing code: singleton classes in `includes/`, `RQRC_`/`rqrc_` prefixes, text domain `reusable-qr-codes`, docblocks, escaping on output, nonces and capability checks on writes.
- The QR post type keeps `show_in_rest => false`. QR codes are still edited in the classic edit screen.

## 1. Logo

### Data

- Settings option `rqrc_settings['qr_logo_id']`: attachment ID of the site logo, `0` = none. It is sanitised with `absint` and must be an image attachment.
- Post meta `_rqrc_logo_mode`: `none` | `site` | `custom`. Missing meta means `none`.
- Post meta `_rqrc_logo_id`: attachment ID, used only when the mode is `custom`.

### Resolution

One PHP helper, `RQRC_Logo::get_logo_url( $post_id )`, returns the image URL to draw, or an empty string:

- mode `none` → empty;
- mode `site` → URL of the site logo, or empty if none is set;
- mode `custom` → URL of `_rqrc_logo_id`, or empty if it is missing or not an image.

Use the `large` size if it exists, otherwise `full`. Every place that draws a QR code uses this helper, so all of them agree.

### Drawing

When a logo URL is present, the QR options get:

- `image`: the logo URL;
- `imageOptions`: `{ hideBackgroundDots: true, imageSize: 0.35, margin: 4, crossOrigin: 'anonymous' }`;
- `qrOptions`: `{ errorCorrectionLevel: 'H' }`, so the code still scans with its centre covered.

Without a logo the options stay exactly as in 1.0.2, so existing QR codes keep their current pattern.

### UI

- Settings page, QR Code Appearance section: a "Site logo" field with Select / Remove buttons (WordPress media modal) and a thumbnail preview.
- Edit screen: a "Logo" box in the sidebar (its own meta box, so the logo can be chosen before the QR code is published), with radio buttons "No logo" / "Site logo" / "Custom image". "Site logo" is disabled when no site logo is set, with a link to the settings page. "Custom image" shows Select / Remove buttons. Changing the choice redraws the preview at once. It is saved with the post, through the existing `save_post_rqrc_item` handler and the existing nonce.
- The list-page PNG/SVG buttons draw the logo too. Each row carries its resolved logo URL in a data attribute.

## 2. Block "QR Code"

### Registration

- Name `reusable-qr-codes/qr-code`, from `blocks/qr-code/block.json` (apiVersion 2, category `widgets`, a QR-like dashicon).
- PHP registers it with `register_block_type( <dir>, array( 'render_callback' => … ) )`. Dynamic block: `save` returns `null`.
- Attributes:
  - `qrId` (number, default 0)
  - `size` (number, default 200; the editor limits it to 100–600 px)
  - `showCaption` (boolean, default false)
  - `caption` (string, default ""; empty means "use the QR code's title")
  - `showDownload` (boolean, default false)
- Supports `align: ["left","center","right"]` and `html: false`.

### Editor

- The editor script (`blocks/qr-code/editor.js`) is enqueued on `enqueue_block_editor_assets`. It depends on `wp-blocks`, `wp-element`, `wp-block-editor`, `wp-components`, `wp-i18n` and the QR library.
- The list of QR codes to choose from comes from `wp_localize_script`: ID, title, permalink, resolved logo URL, plus the site-wide colours and dot style. Published QR codes only, sorted by title. No REST changes.
- Sidebar (InspectorControls): a SelectControl for the QR code, a RangeControl for the size, a ToggleControl for the caption plus a TextControl for the caption text, and a ToggleControl for the download button.
- The canvas shows a live preview drawn with the QR library: the QR code, the caption and a disabled download button when those are on. With no QR code chosen, it shows a Placeholder with the same SelectControl.

### Front end

The render callback outputs nothing when `qrId` is not a published `rqrc_item`. Otherwise it outputs:

```html
<figure class="wp-block-reusable-qr-codes-qr-code [alignX]">
  <div class="rqrc-block-qr" style="width:{size}px;height:{size}px" data-rqrc='{json}'>
    <noscript><a href="{permalink}">{title}</a></noscript>
  </div>
  <figcaption>{caption or title}</figcaption>            <!-- only when showCaption -->
  <button type="button" class="rqrc-block-download">Download QR code</button>  <!-- only when showDownload -->
</figure>
```

- `data-rqrc` holds the permalink, size, colours, dot style, logo URL and a sanitised filename base. It is JSON-encoded and escaped with `esc_attr`.
- The view script `blocks/qr-code/view.js` and the QR library are enqueued from the render callback, so they load only on pages that contain the block, in the footer. The script draws each `.rqrc-block-qr` and wires the download button: PNG at 1024 px, using the same sanitizeFilename logic as the admin.
- The fixed box size reserves the space, so the page does not jump when the code is drawn.
- An inactive QR code still renders; scanning it goes to the home page, as before.

## 3. Scan counter

### What counts

The counter increments in `RQRC_Redirects::handle_redirect()` for every view of a published QR code's URL: a redirect to the destination, a redirect of an inactive code to the home page, or the "not configured" page. The request is skipped when:

- the method is not GET (HEAD requests from link checkers are skipped);
- `is_user_logged_in()` is true;
- the user agent is empty or matches a filterable bot pattern (filter `rqrc_bot_user_agent_pattern`). The default pattern, case-insensitive: `bot|crawl|spider|slurp|facebookexternalhit|facebot|whatsapp|telegram|slack|discord|skype|linkedin|embedly|preview|pinterest|vkshare|w3c_validator|curl|wget|python|go-http|java/|headless|lighthouse|monitor`.

### Storage

- `_rqrc_scan_count`: integer.
- `_rqrc_last_scan`: UTC datetime, `Y-m-d H:i:s`.

The increment is one atomic SQL `UPDATE … SET meta_value = meta_value + 1` through `$wpdb`, after `add_post_meta( …, 0, true )` makes sure the row exists. Then the post meta cache is cleared. This avoids lost counts under concurrent scans.

### UI

- List page: a "Scans" column after Status, showing the count and, under it, "Last: {human time diff} ago" or "Never".
- Edit screen: a "Scans" box in the sidebar showing the count, the last scan as a site-local date, and a "Reset" button. The reset uses AJAX with its own nonce and an `edit_post` check, and asks for confirmation first.

### Caching

Most page caches do not store redirect responses. Testing checks that a repeated scan increments the count on the test site. The readme FAQ says that full-page edge caches configured to cache redirects can hide scans.

## Readme and version

- Version 1.1.0 in the plugin header, `RQRC_VERSION` and `Stable tag`.
- Key Features gains the logo, the block and the scan counter. The "Privacy Friendly" line changes to "no personal data, no cookies, no external calls".
- These FAQ answers change: logo (yes, optional per QR code), scan tracking (yes, a simple counter, no personal data), frontend display (yes, with the QR Code block).

## Out of scope

Per-day scan history, charts, CSV export, a shortcode, REST endpoints, logo upload outside the media library, SVG logos.

## Testing

There is no automated test suite. Each task is verified on the throwaway Docker site (WordPress 7.1.2; Twenty Twenty-Five, plus Twenty Twenty-One for one classic-theme check):

- `php -l` on every changed PHP file. Plugin Check reports no new code warnings.
- Existing QR codes with no logo render the same pattern as before: compare the generated SVG for one existing code before and after.
- Logo: each mode in the edit-screen preview, the PNG download, the SVG download and the list download; a decode check that a logo QR code still decodes to its URL (zbarimg, or the BarcodeDetector API in Chromium).
- Block: insert, choose a code, change size, caption and download in the editor; the front end draws the same code; the download works; no console errors; scripts load only on pages with the block.
- Counter: an anonymous `curl` with a browser user agent increments the count; a logged-in request, a HEAD request and a bot user agent do not; reset works; concurrent requests (20 in parallel) give an exact count.
- Uninstall still removes all data, including the new meta and the settings key.
